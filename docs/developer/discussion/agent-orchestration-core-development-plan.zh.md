# DSH 原生 Crew 智能体编排开发步骤

[English](agent-orchestration-core-development-plan.md) | 中文

这是第一阶段除外部 CLI 适配器之外所有编排功能的实施顺序。它让当前 DSH Agent 成为厂长，让 DSH 可续接子智能体成为工人，并让现有 Web 应用成为唯一用户入口。

## 摘要

产品应构建为现有 Agent Teams 与子智能体能力之上的 Crew 工作流。根 Session Agent 就是厂长；它已经接收用户回合，不应再包一层常驻 CLI 进程，也不应通过 MCP 桥接回 DSH。工人是由进程内提供方创建的 DSH 原生可续接子智能体。Agent Teams 继续作为持久成员表、信箱和依赖感知任务底座；Crew 增加软件工作流阶段、硬验证、厂长通知、整合与提交门禁、角色预设和右侧 UI。

根 Session 日志是权威数据。不得新增 `board.json`、第二套信箱或以进程内任务注册表作为产品状态。仓库 `docs/` 与测试是持久工作产物和恢复证据，但不替代 Session 投影。

## 范围与固定决定

| 主题 | 第一阶段决定 |
|---|---|
| 厂长 | 当前顶层 DSH Session Agent；用户继续向它发送普通回合。 |
| 工人 | 通过 `subagent-spawn-in-process` 使用 DSH 可续接子智能体；不使用外部 CLI 提供方。 |
| 协作 | 复用 Agent Teams 的成员表、信箱、任务、依赖和冷恢复。 |
| 产品工作流 | 增加引用 Team 成员和任务的 Crew 领域，由它负责软件开发阶段与门禁。 |
| 状态权威 | 向厂长 Session 日志追加事件，并在回放时投影。 |
| 仓库产物 | 厂长编写项目/模块规格，工人编写日志与测试；用于交接，不是工作流数据库。 |
| 工作树模式 | 第一阶段共享一个 checkout，模块范围互斥；拒绝活动范围重叠。 |
| 用户交互 | 只与厂长对话；工人详情只读，但可有明确审批控件。 |
| 提交 | 在全部静止、验证、整合和用户认可后调用宿主拥有的 Crew 工具；厂长和工人的普通 shell 都不能写 Git 状态。 |
| 外部提供方 | 全部延后到独立的 [CLI 调查](agent-orchestration-cli-integration-research.zh.md)。 |
| 平台 | 本阶段在原生 Windows 上开发与验收。Linux 兼容适配和本地 Linux/WSL 验证延后，不阻止 Windows 交付。macOS 不纳入主动开发、测试或兼容适配。保留现有兼容代码，具体问题按对应平台的复现和修复处理。 |

<a id="target-runtime"></a>

## 目标运行时

Web profile 组合一个根 Agent、Crew 服务与厂长工具、Agent Teams、DSH 原生可续接提供方、Crew 角色预设和 Crew Web 投影。一次厂长派工会创建 Team 任务与可续接子智能体，在 Crew 工单中绑定它们的品牌化标识，然后立即返回。子智能体通过标准 Agent loop 运行，并把自身的模型/工具历史记录在子 Session 中。

子智能体终止后，宿主验证器检查仓库并运行声明的聚焦测试。只有宿主能把工单推进到可审查状态。审查工人接收只读证据；打回会把修复回合追加到原开发子智能体。全部模块通过后，整合工人检查组合后的 checkout。只有用户接受交付且所有门禁仍然通过，厂长才能请求提交。

厂长唤醒是普通的排队 Session 回合，不是独立厂长进程。Crew 服务记录持久通知批次，在可配置时间窗内合并事件，并在当前厂长回合结束后通过正常 Session 输入队列提交。交付在重启后保持幂等，发送给模型的每个字节都能从日志事件重建。

<a id="persistent-records-and-states"></a>

## 持久记录与状态

Crew 复用 `TeamId`、`TeamTaskId` 和子 `SessionId`。只有独立生成的记录确实需要标识时，才新增品牌化工单、验证、审查、整合和通知标识。第一阶段不存在提供方 session ID。

第一版实现应冻结整值、带版本的 Session 事件，覆盖配置、工单状态、验证结果、审查结果、整合结果、厂长通知入队和通知交付。整值事件让投影与迁移保持明确；已提交事件世代遵循仓库的相邻迁移规则。

| 记录 | 必需事实 |
|---|---|
| Crew 配置 | 仓库根、角色预设、并发数、合并间隔、回合/时间限制、审查上限、允许的测试命令形式和提交策略。 |
| 工单 | Team 任务 ID、模块键、规格路径与修订、读写范围、开发子 Session ID、阶段、原因、计数器和最近接受的验证 ID。 |
| 验证 | 精确命令、cwd、退出结果、必需产物、变化路径、越界项、开始/结束事实和来源子智能体终态。 |
| 审查 | 审查子 Session ID、检查的规格修订与验证 ID、结论、结构化问题、轮次和终止原因。 |
| 整合 | 整合子 Session ID、包含的工单与验证 ID、组合测试结果、结论和各故障对应负责人。 |
| 通知 | 有序来源事件 ID、面向厂长的简短内容、入队状态、已交付输入标识和可安全重试的确认。 |
| 提交决定 | 用户认可输入标识、静止证明、当前验证与整合 ID、暂存路径、消息及最终 commit hash 或拒绝。 |

使用由 Crew 服务拥有状态转移的小型工作流阶段联合：`planned`、`queued`、`running`、`verifying`、`reviewing`、`revision_required`、`integration_ready`、`accepted`、`paused`、`failed` 和 `cancelled`。UI 颜色与标签是派生展示，不作为独立事实持久化。

Team 任务继续负责依赖就绪与分配。只有被引用的 Team 任务、子智能体生命周期和宿主证据一致时，Crew 阶段才可推进。不变量模块必须比较这些独立观察值并拒绝不可能组合。

<a id="enforcement-model"></a>

## 强制执行模型

以岗位职责驱动协作，主智能体结合用户偏好判断，工具层执行必要的项目路径与审批检查。Windows 交付不以额外的操作系统沙箱为前提。

1. 工人预设在创建子智能体时提供允许的 persona、模型选项、工具筛选、cwd、可读根和可写根；这些值保存在可续接描述符中，并在冷恢复时重新应用。
2. 开发智能体的文件工具限制在分配的模块与共享 `docs/`、`test/`、`tests/` 目录内。审查智能体读取完整项目，整合智能体为整合工作读写完整项目。额外操作交给主智能体判断，并取得必要的用户批准。
3. 终止验证独立读取 Git status 与 diff 路径、必需产物和声明测试。Team `writeScopes` 继续只是范围重叠提示元数据，绝不视为安全边界。
4. 审查智能体独立检查需求、实现与测试，将具体问题交还原开发智能体。整合智能体可以进行跨模块修改并运行组合测试。宿主提交工具在暂存与提交前重查实际的最终 checkout。

文件工具依据选定项目规范化路径，并检查路径与链接逃逸。获准命令通过 DSH 现有子进程提供方在实际项目中运行，使用已安装依赖，保留输出文件，并具有超时、取消和进程树清理。这些检查不宣称操作系统隔离，也不会把任意脚本变成安全命令。

厂长预设可创建规格、共享接口和脚手架，但其普通 shell 不能写 Git。`crew_commit` 是 profile 中唯一 Git 写能力。该工具要求厂长 Session 内当前有效的用户认可标记，且永不 push。

<a id="global-memory-and-role-models"></a>

## 全局记忆与岗位模型

固定的主智能体系统提示词规定读取记忆、规划分工、协调岗位、识别危险操作与主动告知用户的职责。附带 Skill 说明何时读取、使用和更新记忆。可变的用户习惯不写进系统提示词。

DSH 将操作偏好与明确的范围授权保存在用户全局设置中，不放进项目目录或仓库。用户可以查看、修改、删除每条记忆。过去经常批准是偏好，不是长期许可；长期授权必须取得用户对适用范围的明确批准，危险命令仍需说明目标、影响与可恢复性。工具权限检查继续具有最终约束力。

复用现有 Agent 上下文钩子，在主会话开始或恢复时提供有日志记录的当前记忆。被删除条目必须从下一份权威记忆快照中消失。项目规格、任务进度与工人历史继续保存在各自的项目和 Session 归属处，不进入全局操作记忆。

用户可以分别选择主、开发、审查、整合四个岗位的提供方、模型与思考档。创建 Agent 时解析默认值；已有子会话及返工回合保留已保存的模型绑定。在现有 Web UI 中提供全局设置编辑器与实时只读子会话记录。默认 Web 和桌面入口必须保留普通 DSH 功能，并直接显示 Crew，无需额外启动命令。

<a id="manager-and-worker-lifecycle"></a>

## 厂长与工人生命周期

### 厂长回合

1. 与用户澄清目标、非目标、约束和可观察验收。
2. 编写或更新项目规格、模块规格、共享接口、依赖顺序、聚焦测试命令与互斥路径范围。
3. 对已就绪模块调用 `crew_dispatch` 并结束回合；工人运行期间绝不轮询或 sleep。
4. 收到已记录 Crew 通知后，处理暂停或失败工作，向用户报告实质选择，并只通过 Crew 工具追加或换人。
5. 整合通过后汇总证据、取得用户认可；用户要求提交时再调用 `crew_commit`。

### 开发工人回合

1. 阅读分配规格、当前模块状态、引用接口和以前的开发日志。
2. 只修改允许的模块、测试与日志路径；只运行声明的聚焦命令。
3. 通过 DSH 原生输出 schema 产生结构化工人结果。
4. 让宿主验证器决定权威状态转移；工人声称 `done` 不能自行完成工单。
5. 修订时继续同一子 Session，除非恢复明确证明它不可用。

### 审查与整合回合

1. 审查读取一个冻结的规格修订、变化路径证据、开发日志和宿主验证；不编辑文件。
2. 打回会记录结构化文件/行/问题/预期项，并追加到同一开发子智能体，直到配置的审查上限。
3. 只有每个纳入模块都有当前通过的审查且没有活动工人时，才能开始整合。
4. 整合运行组合测试和接口检查，记录结构化结论，并标识每项故障负责的工单。
5. 审查智能体要求原开发智能体修正实现问题，整合智能体负责必要的整合修改并报告每条变化路径。两者都与主智能体协调，将 Git 提交留给获批的宿主工具。

### 停止、失败与重启

1. 停止会中断活动子智能体回合，在有界时间内等待终止，并在不删除可续接描述符的情况下标记结果。
2. 失败工人保留 Session、日志、原因和最近验证的仓库状态；重试与换人是两个不同的厂长动作。
3. 应用重启时回放根 Crew 与 Team 投影，核对子智能体描述符和当前 Git 事实，只恢复持久状态中确实活动的记录。
4. 关机前入队的通知最多向厂长交付一次；已交付通知不会重建成新的模型输入。
5. 缺失或损坏关系必须带标识和恢复指引明确失败，而不是创建空白工人。

<a id="web-client-design"></a>

## Web 客户端设计

现有布局继续是侧栏、厂长对话和右侧详情栏。把聊天拥有的详情面板泛化成有类型的视图选择链。现有工具调用详情成为一个可选择视图，Crew 注册另一个；打开 Crew 不会卸载厂长对话，也不会创建新的路由级应用。

Crew 面板显示项目状态、厂长状态、上方活动工人、下方完成工人、模块、角色、阶段、简短原因、子 Session 短 ID、当前验证、审查轮次与整合状态。选择工人后，打开从 Session 投影派生的只读结构化详情和有界日志摘录。它绝不挂载标准子智能体输入框，也不暴露“继续此工人”的输入。

审批控件是明确的宿主交互，不是与工人聊天。每个控件显示请求操作、已解析目标、策略原因、决定有效期和结果状态。DSH 原生第一阶段策略可拒绝没有受支持窄审批的操作；面板不得暗示每次拒绝都能覆盖。

Remote 方法返回有类型的投影和 CAS 修改。实时更新使用现有客户端服务/存储模式与订阅或变化游标；打开面板不是刷新机制。产品文案放在带类型的中英文字典中，状态颜色同时配有文本和图标语义，键盘与焦点行为由浏览器测试覆盖。

<a id="implementation-milestones"></a>

## 实施里程碑

### M0 — 冻结约定与夹具

归属路径：拟议 Agent Note、本文、新包中的 Crew 类型草图和首个录制会话场景清单。

- 在 UI 工作前，把架构决定转换成精确服务请求、事件载荷、状态转移表、工具 schema、角色预设和错误码。
- 清点新 Session 事件影响的每处模型可见提示/工具变化以及 TypeScript/Python SDK 投影。
- 定义一个包含共享接口、独立测试、一次审查打回、一次修复、整合和活动时提交拒绝的双模块夹具仓库。
- 为非法转移、过期修订、范围重叠、未授权工具和重复通知交付增加失败中的约定测试。

退出门禁：评审者能把每条验收追踪到所属包、事件、测试和模型可见快照；没有实施决定依赖外部 CLI。

### M1 — 实现持久 Crew 领域

归属路径：`packages/subagent/crew/` 和经其测试证明必需的通用 Agent Team 修正。

- 实现配置验证、品牌化标识、版本化事件声明、append-and-flush 事务、回放投影、状态转移授权和不变量。
- 把每个 Crew 工单绑定到一个 Team 任务，保留 Team 的依赖和所有者语义，不复制任务板。
- 为厂长工具与 Web 客户端暴露只读视图，并为宿主操作提供 CAS 修改请求。
- 证明并发修改、每个事件边缘后的回放、不完整末尾 JSONL 恢复、释放和 HMR 清理。

退出门禁：新建服务与回放服务返回相同的分离投影；非法 Team/Crew 组合以稳定错误码失败。

### M2 — 派遣 DSH 原生可续接工人

归属路径：`packages/subagent/crew/`、`packages/subagent/tool-crew/`、角色预设夹具，以及全部提供方都需要的通用子智能体变化。

- 实现仅厂长可用的 `crew_dispatch`、`crew_append`、`crew_stop`、`crew_status` 与 `crew_reassign` Consumer，并返回简短结果。
- 在派工时显式解析 DSH 原生提供方、角色 persona、模型、思考档、工具筛选、限制、cwd 与路径策略，并为续接快照这些值。
- 以可恢复顺序创建 Team 任务与子智能体，并为部分失败写入补偿性终态事件。
- 通过现有子智能体服务路由追加、中断、终止与冷恢复；不维护第二套进程注册表。

退出门禁：两个互斥工人可并发运行，追加保持同一子 ID，停止可干净终止，重启从持久描述符恢复且不重复任务或子智能体。

### M3 — 强制范围与权威完成

归属路径：Crew 验证模块、文件系统与 shell 策略集成、测试夹具和包文档。

- 对全部声明范围实现按组件的真实路径检查，并拒绝活动工单之间范围重叠。
- 默认给开发者范围受限的文件工具和已声明的项目测试。额外操作交由厂长和现有用户审批策略处理，不从记忆偏好推断授权。保留凭据与 Git 内部文件检查。
- 在模型输出边界解析 DSH 原生结构化结果，再独立检查必需产物、Git 路径与精确聚焦测试命令。
- 对失败的交接检查自动追加一次有界修复，然后带持久证据暂停，而不是循环。

退出门禁：开发文件工具拒绝相邻模块与项目路径逃逸，共享文档和测试访问可用；获准的 Windows 项目脚本成功运行；虚假 `done` 声明不会推进到审查。测试不得宣称文件工具范围能够约束任意子进程代码。

### M4 — 增加审查、整合与提交门禁

归属路径：Crew 审查/整合/提交服务、厂长工具、按岗位配置的角色预设和 Git 操作测试。

- 权威开发验证后自动派遣只读审查子智能体；冻结其输入证据 ID。
- 记录通过或结构化打回；把打回追加到原开发子智能体，并强制配置的审查轮次上限。
- 只对静止、全部通过审查的依赖集合实现 `crew_integrate`；给整合者完整项目权限以执行必要的跨模块编辑，要求其报告这些编辑，并由宿主运行测试验证组合结果。
- 实现带用户认可证明、最后时刻状态重查、精确暂存集合、提交消息验证且不 push 的 `crew_commit`。

退出门禁：工人都不能提交，运行中或过期世界拒绝提交，被打回审查返回同一开发子智能体，只有当前有效的整合通过结果可提交。

### M5 — 交付事件驱动厂长回合与重启恢复

归属路径：Crew 通知日志、Session 输入集成、调度器生命周期和重启/并发测试。

- 分类需要厂长行动的终态事件和只更新 UI 的进度事件。
- 在可配置时间窗内合并可操作事件，调度前持久化有序批次，并在活动厂长回合终止后提交。
- 记录交付标识和确认，使提交前后崩溃点都能无丢失、无重复地回放。
- 启动时核对活动记录、子智能体运行态、Session 队列和仓库事实；绝不只因进程不存在就推断完成。

退出门禁：工人可在厂长回合期间以任意顺序完成，厂长随后只收到一个已记录批次；在每个崩溃点重启都保持模型可见消息恰好一次。

### M6 — 构建只面向厂长的 Web 体验

归属路径：`packages/client/ui-crew/`、`ui-chat` 详情视图扩展、Remote 组合、本地化字典和浏览器测试。

- 在不改变三栏布局的情况下泛化单个详情拥有者，并保留现有工具详情行为。
- 增加实时项目/工人列表、派生状态展示、只读工人详情、验证/审查/整合证据和受支持审批控件。
- 保持厂长输入框为唯一自由文本用户输入，阻止 Crew 导航选择普通可编辑子智能体会话视图。
- 覆盖加载、空、过期、重连中、失败、窄窗口、键盘、读屏和本地化状态。

退出门禁：右侧面板无需重新打开即可更新，工具详情继续工作，不可到达工人输入框，浏览器测试证明双语与非颜色状态线索。

### M7 — 组合 profile 并证明交付路径

归属路径：Crew 无头/Web profile 包、预设目录、快照夹具、需要时的两个 SDK 预期输出和所有受影响双语 README。

- 只通过 Crew profile patch layer 组合有文档记录的插件，并且产品只通过 `dsh --profile` 启动。
- 增加一个厂长预设和互相独立的开发、审查、整合预设，各自有显式工具集；缺少预设时在 profile 加载阶段拒绝。
- 通过交付 profile 录制双模块无密钥场景，包括子智能体、打回/修复、厂长通知、整合、UI 状态和预期工作区。
- 运行聚焦包测试，然后执行与变化面匹配的构建、类型、lint、文档、hygiene、快照和 Web 门禁。

退出门禁：干净 Windows checkout 无需提供方登录即可回放完整产品路径；每条第一阶段验收都有外部世界证据，而不是 Agent 自述。

<a id="verification-strategy"></a>

## 验证策略

本阶段以原生 Windows 验收为准，包括现有 Web 应用、Crew 交付 profile、重启恢复、两个 SDK 投影、按岗位限制的文件访问、实际项目命令和 `agent-test` 中的真实 DeepSeek 工作流。平台特有的夹具差异需要提供同一用户行为的 Windows 原生证据；跳过 Linux 用例不等于 Windows 通过。命令验证必须覆盖子进程取消和进程树清理，不能宣称具备 OS 隔离。Windows 桌面验收还包括托盘收起与恢复、活动工作二次确认、持久停止和完整后台进程树清理；仍不包含外部 CLI 适配器。保留现有 Linux CI，但本地 Linux/WSL 调查和 Linux 全量回放不作为本阶段的前置条件（[维护范围](../../../.agents/notes/implemented/process/2026-09-05-windows-linux-maintenance-scope.zh.md)）。

| 层次 | 必需证据 |
|---|---|
| 单元 | 状态转移表、配置与线协议验证、品牌化 ID、路径包含、命令策略、事件合并、错误分类、纯 UI presenter 和本地化完整性。 |
| 并发 | CAS 冲突、两个工人终止、追加/停止竞态、通知合批、HMR 释放和共享宿主调度下的有界拆除。 |
| 持久化 | 每个事件后回放、不完整末尾处理、子智能体冷恢复、通知崩溃点和 Git 事实核对。 |
| 构建产物集成 | 通过构建导出完成 Loader/profile 组合，并运行真实 DSH 原生子 Agent loop，只脚本化模型适配器。 |
| 快照 | 无密钥厂长与子 Session、精确模型可见 Crew 工具与通知、SDK 投影和工作区预期树。 |
| Web | 真实浏览器渲染、右栏实时更新、详情视图共存、只读工人 UX、可访问性与重连行为。 |
| 安全 | 文件系统与 shell 逃逸尝试、链接穿越、相邻模块写入、Git 写入、依赖安装、过期提交和未授权 Team 成员调用。 |
| 手工冒烟 | 启动交付 Crew Web profile，派两个模块，观察实时状态，重启 DSH，修复一个模块，整合、认可并本地提交。 |

开发期间使用覆盖每次编辑的最小聚焦命令。声称阶段完成前，根据仓库 pre-push skill 选择适用门禁，并只报告实际运行过的命令。预期命令集合包括 `pnpm run typecheck`、`pnpm run lint`、`pnpm run build`、`pnpm run hygiene`、`pnpm run test:docs`、`pnpm run doc-sync`、`pnpm run test:snapshot -t crew-native` 和相关 Web 浏览器门禁；这不表示每个里程碑后都要运行全部命令。

任何 `SessionEventMap`、loop 生命周期或模型可见输入变化，都必须在同一变更中更新 TypeScript 与 Python SDK 预期输出和录制会话场景。任何能力、生命周期、并发、子进程或拆除变化，也必须执行相应 defensive-pattern 审查并添加聚焦失败测试。

<a id="first-phase-acceptance"></a>

## 第一阶段验收

1. 用户打开一个仓库，并且只与顶层 DSH 厂长 Agent 对话。
2. 厂长无需外部 CLI 即可创建项目/模块规格、互斥范围、依赖、角色绑定、聚焦测试与限制。
3. 厂长派遣至少两个 DSH 原生工人，结束回合，并在持久右侧列表中看到二者。
4. 追加变化需求会续接同一个开发子 Session，并保持可见短 ID。
5. 关闭并重新打开 DSH 后，从日志重建厂长、Team、Crew、子智能体、任务、验证、审查和通知状态。
6. 工人不能越界写入、写 Git、安装依赖、访问凭证或获得等价的不受限工具。
7. 工人自述不能完成工单，直到宿主路径、产物和聚焦测试检查通过。
8. 审查打回无需用户消息或新建子智能体即可到达同一开发工人；重复打回在配置上限暂停。
9. 进度更新不消耗厂长回合即可改变右栏；可操作终态事件被记录、合并并在当前回合后交付。
10. 工作仍活动或状态过期时不能开始整合；整合记录组合测试与接口证据。
11. 未获用户认可、仍有活动工作、checkout 漂移或缺少当前整合证据时拒绝提交；成功提交只暂存获批路径且永不 push。
12. 厂长对话继续是唯一自由输入；可查看工人详情、日志、结果和审批，但没有可编辑子输入框。
13. 交付 profile 与浏览器路径通过无密钥录制回放，并有外部验证的预期工作区。
14. 第一阶段运行时代码和设置中不存在 Gemini CLI、Claude Code、Codex、Grok、Antigravity、登录和额度行为。

<a id="deferred-work"></a>

## 延后工作

- 本地 Linux/WSL 环境恢复、Linux 全量回放和 Linux 专属兼容修复；明确重新纳入平台验证范围后再开展。
- 系统 Claude Code、Codex app-server、Grok ACP 与 Antigravity `agy` 适配器，包括提供方认证与额度展示。
- 自动提供方选择、跨提供方换人、提供方专属价格和订阅优化。
- Worktree、远程仓库、多用户、分布式工人和跨主机调度。
- 用户直接与工人对话或不受限接管工人。
- 美术、建模和非软件角色模板。
- 实验 Crew 或 Agent Teams API 的公开稳定化。

<a id="risks"></a>

## 风险

| 风险 | 缓解 | 发布信号 |
|---|---|---|
| 共享 checkout 让一个模块的半成品泄漏到另一个测试。 | 要求路径互斥、独立聚焦测试、派工前完成共享接口脚手架，并且只在静止后整合。 | 两个并发夹具工人产生确定性模块测试和稳定组合结果。 |
| 工具筛选看似严格，但 shell 或链接能绕过。 | 在提供方解析有类型的操作和真实路径，回合后再独立验证 Git 路径。 | 逃逸夹具在执行时和终止时都被拒绝。 |
| Crew 复制 Agent Teams 并发生漂移。 | 通用成员、任务、依赖与信箱只存 Agent Teams；Crew 只记录引用和工作流证据。 | 回放不变量拒绝孤立或矛盾标识。 |
| 厂长通知在崩溃边缘丢失或重复。 | 持久化入队与交付标识，与 Session 队列串行化，并测试每个崩溃边缘。 | 重启矩阵在模型输入中恰好观察每个批次一次。 |
| UI 直接读取进程状态。 | 通过 Remote 提供带类型 Session 投影，并在纯客户端代码中派生展示。 | 浏览器重连无需活工人进程即可重建相同面板。 |
| 普通工具绕过提交门禁。 | 从厂长和工人预设移除 Git 写能力，只暴露宿主拥有的 `crew_commit`。 | 安全测试使每条替代 Git 写路径失败。 |
| 实验包意外成为永久平行架构。 | 交付路径快照后定义晋升或删除标准，评审前不公开导出。 | 后续 Agent Note 明确晋升、合并或删除实验实现。 |
