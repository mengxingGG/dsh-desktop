# Agent Note: Crew 岗位策略与用户全局操作记忆

Status: implemented

[English](2026-09-05-crew-role-policies-and-global-memory.md) | 中文

## 问题

操作偏好属于用户，跨项目使用。将其与仓库一同保存，会在切换项目时丢失，也可能通过 Git 发布私人习惯。把反复批准视为长期许可还会悄悄扩大权限。独立岗位模型不能改变正在工作或返回返工的开发者所用模型。

Crew 的私有命令快照和 OS 专用限制，使普通 Windows 项目测试无法使用已安装依赖与子进程管道。只读整合者可以报告接口问题，却无法执行其职责所需的跨模块修改。

## 决策

[Crew 偏好插件](../../../../packages/subagent/crew/src/preferences.ts)向现有 [DSH 设置提供方](../../../../packages/settings/settings-file/README.zh.md)注册一个命名空间。[统一 home 解析器](../architecture/2026-07-24-single-harness-home-resolver.zh.md)、[设置归属](../../archived/architecture/2026-07-28-user-settings-seam.md)与[浏览器设置镜像](../../archived/architecture/2026-08-17-settings-describe-mirror.md)继续具有权威性。不新增项目记忆文件、浏览器本地持久记忆或第二套偏好数据库。项目规格、任务进度与 transcript（文本记录）保持现有归属。

条目区分操作偏好与明确限定范围的授权。厂长记忆工具保存授权前始终取得通用审批。Web 编辑器使用专门的授权确认。两条写入路径都保留观察到的设置 revision，因此陈旧草稿不能覆盖较新的选择。删除使条目不再进入后续权威快照，但不重写历史 Session 消息。

厂长上下文钩子在每轮首个继续执行的步骤（包括恢复）及轮次内记忆变化后，将当前记忆追加为已记录的用户消息。其文本替换旧快照，并要求危险操作说明目标、影响与可恢复性。偏好帮助判断，不绕过工具策略。四个独立模型默认值在创建时生效。已有工人描述符、返工 Session 和已记录厂长请求头保持所选模型。[默认模型服务](../../../../packages/core/agent-default-model/README.zh.md)接受精确 Agent 解析器，让 Web 提示变量和路由共享岗位默认值，同时显式会话选择仍然优先；岗位变化不写入部署默认值。

开发者文件工具允许任务模块路径和已配置共享目录，默认共享 `docs`、`test` 与 `tests`。审查者读取完整项目并运行声明测试，不进行编辑。整合者读写完整项目，报告其额外变更路径，并运行组合测试。文件工具继续执行凭据、Git 内部路径、路径穿越与文件系统别名检查。

声明测试通过现有子进程提供方使用实际项目和已安装运行时。Crew 负责工作目录验证、凭据环境过滤、截止时间、有界输出与受管清理。这些不是 OS 隔离保证：项目测试可以凭用户进程权限访问宿主资源。配置的程序列表与声明命令身份仍是测试工具的限制。测试覆盖 Windows Node 和 npm 项目执行；这些测试不验证 Linux、WSL 或 macOS。

[原生 Crew 工作流决策](2026-09-04-dsh-native-crew-orchestration.zh.md)继续负责持久任务、稳定子 Session、审查返工、通知和提交证据。本决策取代其中的私有执行快照策略与只读整合策略。已移除 LPAC 启动器的创建时 Job 和有序完全停稳记录属于冻结历史，不是当前命令执行器的策略。

## 考虑过的替代方案

**项目拥有操作记忆。**拒绝，因为用户偏好必须在切换项目后保留，且不能进入项目版本控制。项目专用工作产物保持独立。

**从过去批准推导永久授权。**拒绝，因为观察到的行为不是明确授权。授权保留用户声明的范围，且绝不抑制危险操作提醒。

**把全局模型变化应用到已有子会话。**拒绝，因为审查和返工需要原开发者 Session 及其绑定选项保持连续。

**要求每次测试使用私有 Windows/Linux OS 沙箱。**对这个 Windows 优先的原生工作流予以拒绝，因为它阻塞普通项目执行，并重复实现进程启动器。强隔离只能作为明确选择且经过平台原生验证的提供方重新引入，不能从路径范围推导未经验证的保证。

**保持整合只读。**拒绝，因为组合模块包括必要的跨模块编辑；已审查模块修改与后续整合者修改都成为最终验证的显式输入。

## 验证

[Host 偏好测试](../../../../packages/subagent/crew/tests/preferences.spec.ts)验证独立 DSH home 持久化、重启、范围授权数据、revision 冲突、模型解析和无效输入。[原生工作流测试](../../../../packages/subagent/tool-crew/tests/tool-crew.spec.ts)验证已记录记忆替换、授权审批、稳定工人模型、开发者共享文档、审查者完整项目读取，以及整合编辑与测试。[执行测试](../../../../packages/subagent/crew/tests/execution.spec.ts)覆盖真实 Windows 项目命令、依赖、子进程管道、输出上限、截止时间与取消。

[Web 设置场景](../../../../apps/web/tests/crew-settings.e2e.ts)通过真实浏览器/Host 连接修改四岗位和记忆，验证 DSH home 文件，刷新、编辑、取消删除并确认删除。Client 测试覆盖陈旧草稿、不可用模型、只读设置与带 generation 校验的目录请求。这些检查不证明普通 profile 集成、实时工人 transcript 呈现、桌面壳验收或外部 CLI 适配器。

## 影响

用户可以集中编辑记忆，无需新增存储或同步机制。记忆中的授权仍是模型可见的用户指令，而非可执行权限表达式。记忆和岗位选择使用同一个命名空间 revision，因此并发编辑即使修改不同字段，也可能要求重新打开草稿。

岗位文件检查仍可防止意外跨模块编辑，但任意测试脚本并不受这些路径约束。共享文档和测试写入还需要开发者之间协调。整合报告必须列出实际编辑；验证保留修改后的 checkout，而不要求准入时的 checkout 始终不变。
