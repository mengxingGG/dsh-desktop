# Agent Note: 主智能体主导的 Crew 交付与受控委派

Status: implemented

[English](2026-09-11-manager-led-crew-delivery.md) | 中文

## Problem

为每个模块串联开发、审查和集成子智能体，会重复加载上下文，并为小范围修复消耗额外请求容量。缺少开发工具的主智能体无法收尾接近完成的任务。使用过期验证重试集成，可能诱使智能体通过破坏性操作恢复旧文件摘要。

## Decision

主智能体保留 Shell、文件编辑和搜索工具。它委派完整且独立的职责，复用开发 Session，并直接处理小范围修复和集成。默认派发由主智能体审查；独立审查和专门集成保留为显式选择。自动修复默认次数为零，由主智能体决定下一步恢复操作。[Crew 服务](../../../../packages/subagent/crew/README.zh.md) 拥有参数和证据语义。

主智能体集成拒绝仍有活跃子智能体的工作流，针对当前文件记录新的验证与主智能体审查，失败时保留产物。主 Session 标识执行者，不把主智能体审查表示为独立子智能体审查。现有 Session 代际保持不变。已发布工单缺少 `reviewMode` 时保留独立审查语义；集成缺少 `execution` 时保留子智能体执行语义。

子智能体能力白名单覆盖继承、当前作用域和后续注册，同时约束发现与执行。子智能体不能通过普通子代理或工作流工具获取更宽泛的工具集。这不把已授权的 Host 命令变成操作系统沙箱。

默认子智能体容量为两个活跃工单。独立的 Host 请求池包含主智能体，并将共享账号的提供商路由归为一组。原生流结束时释放名额。外部执行在 DSH 工具运行期间释放名额，在返回工具结果前重新获取，使主智能体等待时不占用子智能体请求容量。

此决定取代[可选预设决定](2026-09-06-crew-orchestration-agent-preset.zh.md)中的强制委派限制，保留其预设列表发布、persona 一致性和组合校验。它也取代[原生 Crew 交付](2026-09-06-native-crew-default-delivery.zh.md)中的逐模块自动审查；持久证据、原生 Session 和可选独立审查仍有价值。

## Alternatives considered

- 只改提示词仍会让额外的作用域工具可调用，也无法修复过期证据处理。
- 始终创建独立审查和集成子智能体会为小任务重复上下文；确有必要时仍可显式请求独立审查。
- CLI 等待工具期间一直占用提供商名额，可能使共享账号的主、子智能体互相等待。
- 删除验证或通过删文件恢复旧摘要会损失交付证据或已完成工作；验证当前文件能同时保留两者。

## Consequences

主智能体可以直接收尾小范围失败，无需创建替代智能体。常规审查只有在显式请求时才具备独立性，完成证据注明审查者。不同路由可能共享凭据，因此由部署配置提供商分组。Host 并发上限无法统计其他应用对同一账号的使用。

必要的回归场景包括作用域工具逃逸拒绝、原开发者续接、修改文件和修正命令后的主智能体恢复、缺失产物、验证期间取消与重启，以及带工具等待的共享账号请求准入。本次交付按用户要求不执行测试。
