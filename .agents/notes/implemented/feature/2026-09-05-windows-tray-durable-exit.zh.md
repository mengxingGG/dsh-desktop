# Agent Note: Windows 托盘与确认后的持久退出

Status: implemented

[English](2026-09-05-windows-tray-durable-exit.md) | 中文

## 问题

关闭桌面窗口必须区分隐藏活动工作与停止应用。已保存的未完成工单不能证明任务仍在执行；在枚举后代之前终止 Windows 进程，可能留下孤儿进程。Cordis 卸载会记录 disposer 错误，因此卸载完成本身不能证明 Session 写入成功。

## 决定

[桌面壳](../../../../apps/desktop/README.zh.md)负责 Windows 托盘与原生确认对话框。收起不改变后端。退出检查实际工作；拒绝确认不改变任务状态。后端在开始准备之前重查未经确认的关停请求。原生文案使用按应用区域设置选择的类型化中英文字典。

桌面壳只为自有启动追加 Web 组合包的 `desktop.patch.yml`。私有继承 IPC 协议传递带序号的活动检查与关停消息，不传递提示词或凭据。普通 Web 启动与渲染器不暴露关停 API。

`dsh-cmdline` 把 `app/active-work` 声明为同步 bail 事件，把 `app/prepare-exit(stage)` 声明为需等待的 parallel 事件。应用先等待 `producers`，再等待 `agents`。生产者关闭准入、取消并排空工作，无法验证清理时拒绝。Crew 在 Agent 工厂关闭写句柄之前停止通知调度。Agent 工厂报告启动、回合及回合间维护；共享关停等待全部自有拆除工作，并在重复请求间保留失败结果。最后的活动检查与 `sessionPersistence.flush()` 必须成功，才会卸载根并回复 `prepared` IPC 消息。

后端在准备后保留 IPC 通道，让父进程枚举仍存活的 Windows 根进程，并在 Electron 退出之前终止完整进程树。父进程不会仅凭 `prepared` 判断进程已退出，而会执行并等待进程树清理。请求失败或超时会保留桌面壳；只有明确选择“强制退出”才允许在没有持久化确认时终止。关停保留已记录历史，不保留运行中的执行，也不承诺自动重放排队输入。

本记录补充[桌面发行决策](2026-08-24-cross-platform-desktop-shell.zh.md)；后者继续约束 Web/profile 归属以及直接运行与安装版的运行时打包。

## 考虑过的替代方案

**每次关闭都直接隐藏，不再询问。** 否决，因为用户必须能区分后台执行与彻底退出。

**只检查界面显示的任务状态。** 否决，因为空闲会话可以保留未完成记录，维护或子进程工作也可能在可见 Agent 回合之外继续运行。

**先终止进程，或把 Cordis 卸载当作保存确认。** 否决，因为取消事件可能仍在缓冲，且卸载会包含 disposer 错误。显式的任务所有者准备与持久刷新保留了可验证的失败路径。

**暴露 HTTP 关停路由。** 否决，因为只有所属桌面进程需要此权限；继承 IPC 避免增加远程可调用操作。

## 后果

正常退出要求准备及进程树清理成功。无响应的生产者或存储失败可能阻止正常退出；警告明确说明强制退出可能丢失未保存状态的取舍。自定义任务生产者必须参与准备并报告活动工作。不增加外部 CLI 适配器或其他操作系统验证。

单元测试覆盖确认竞态、生产者准入、维护取消、关闭与刷新失败，以及可回放的 JSONL 历史。原生 Windows 测试观察后代进程句柄，并使用空闲和流式无密钥任务运行随附的 Web profile。
