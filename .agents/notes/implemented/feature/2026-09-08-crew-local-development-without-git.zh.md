# Agent Note: Crew 无需 Git 的本地开发

Status: implemented

[English](2026-09-08-crew-local-development-without-git.md) | 中文

## Problem

派发时要求已有提交的 HEAD 会阻塞普通项目目录，并使厂长在用户要求本地开发时仍索要 Git 初始化。

## Decision

派发、验证、审查和整合接受普通目录及尚无首次提交的 Git 仓库。文件清单提供内容、类型和权限证据，并记录 `head: null`；已有提交的 Git 观察保留字符串 HEAD 和索引证据。普通目录不会调用 Git 可执行程序。两种模式均不初始化仓库或连接远程。

清单排除受保护的元数据和凭据，记录链接而不遍历，检测采集期间的变化，并跨阶段比较文件摘要。重放接受两种证据形式，并拒绝包含分支或暂存路径的本地证据。产物、范围、声明测试、独立审查和整合要求仍得到执行。

提交是可选操作，需要单独获批，且仅限已有提交的 Git 仓库。提交被拒绝时保留已验收的本地工作。已有仓库的 Git 故障仍明确报告。

此决策部分取代[原生 Crew 决策](2026-09-04-dsh-native-crew-orchestration.zh.md)中仅使用 Git 的假设，该记录继续负责持久工作流、索引检查、所有权和恢复。

## Alternatives considered

- 自动初始化 Git：拒绝，因为是否采用版本控制属于用户决定。
- 在 Git 之外跳过验证：拒绝，因为审查与整合仍需要独立观察到的改动。
- 要求远程仓库：拒绝，因为本地验证和可选提交无需访问远程。

## Verification

宿主测试覆盖普通项目和尚无提交的项目、文件变化、取消、受保护路径及链接。工具测试覆盖过期文件拒绝，以及保留已验收工作的可选提交拒绝。无需密钥的 profile 在不创建 `.git` 的情况下运行双开发者、审查退回、原工人返修与通过整合；其 Git 用例保留提交覆盖。

## Consequences

本地开发无需 Git 即可完成。清单也读取依赖与生成文件，因此成本随项目大小增长；本地模式不应用 Git 忽略规则。文件观察检测变化，但不会隔离并发宿主进程。模型提供方与声明命令的网络需求仍与 Git 分开。
