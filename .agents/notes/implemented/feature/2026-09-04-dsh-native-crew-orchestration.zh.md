# Agent Note: 先实现 DSH 原生 Crew 编排，再接外部提供方

Status: implemented

[English](2026-09-04-dsh-native-crew-orchestration.md) | 中文

## 问题

拟议的一人软件工作室需要一个厂长对话、持久工人、模块范围工作、审查与整合循环、硬完成与提交检查、重启恢复和实时工人面板。较早方案让这些产品保证首先依赖多个外部 CLI 运行时、常驻厂长进程、桥回 DSH 的 MCP 和独立 `board.json`。

DSH 已有相关原生机制：顶层 Session Agent、可续接进程内子智能体、持久子描述符、Agent Teams 成员/信箱/任务记录、Session 事件投影和三栏 Web 客户端。在产品工作流验证前构建第二套编排运行时，会重复标识、队列、恢复和日志。

## 决策

第一阶段完全使用 DSH Agent。当前顶层 Session Agent 是厂长，接收正常用户回合。DSH 可续接子智能体作为开发、审查和整合工人。此阶段不需要也不选择外部 CLI。

Agent Teams 继续作为通用 Team 成员、消息、任务所有权、依赖和建议性写入范围重叠的权威。`@deepseek-ai/dsh-crew` 引用 Team 与子 Session 标识，负责软件工作流配置、阶段、宿主验证、审查证据、整合证据、厂长通知批次和提交决定。

Crew 记录以带版本的整值事件持久化在厂长 Session 日志中，并通过投影重建。子模型与工具历史留在各自子 Session。仓库规格、日志与测试是工作产物和恢复证据，不是第二套工作流数据库。实现中没有 `board.json`。

`@deepseek-ai/dsh-tool-crew` 通过 Crew profile 向厂长暴露专用控制；该 profile 此后已由 [Crew 交付决策](2026-09-06-native-crew-default-delivery.zh.md)晋升出 `packages/experimental/` 并进入默认 Web profile。工人预设在可续接描述符中保留岗位 persona、模型选项、工具筛选和限制。[岗位策略与全局记忆决策](2026-09-05-crew-role-policies-and-global-memory.zh.md)取代私有命令快照和只读整合；本记录保留持久工作流与生命周期决策。

会话究竟要不要启用 Crew，已不再由本记录中那条唯一的自行判断规则决定：[编排预设决策](2026-09-06-crew-orchestration-agent-preset.zh.md)把它变成所选 Agent 预设的选择，并把被强制会话的厂长 persona 与工具集移入 `crew-manager`。

执行限制属于不可变的厂长配置，而不是进程全局 Host 实例。冷恢复后，即使部署默认值不同，每项 Host 操作仍接收已记录的限制。配置、命令和回放验证会拒绝超出 Node 定时器范围的时长，避免长截止时间变成立即超时。

按路径文本排除凭据无法识别普通文件别名。因此，Crew 文件访问要求提供方观察到的硬链接数量为一；缺少元数据意味着拒绝，而不是默认放行。本地文件系统提供方负责报告这一观察结果，不会把 Crew 策略强加给普通文件系统 Consumer。

验证记录声明测试结束后的 checkout。审查完成和整合准入拒绝陈旧的模块输入、规格、HEAD 或分支。岗位策略决策允许已报告的整合编辑，并在组合测试期间检查修改后的 checkout。只有证据标识并不足以授权已变化的文件。

[本地开发决策](2026-09-08-crew-local-development-without-git.zh.md)将验证扩展到没有 Git 元数据或首次提交的文件清单。Git 索引证据和可选本地提交检查仍适用于已有提交的仓库。

即使保留下来的记录能成功解析，不完整的进程输出尾部也不能证明仓库状态。Crew 的 checkout 读取会拒绝截断的 Git 输出与哈希失败，不会把它们当作删除。已完成的 Git 写操作不会因诊断输出截断而变成未完成；其效果由重新检查 checkout 确认，而不是由诊断尾部确认。文件内容相同不代表可执行输入相同，因此已变化路径的摘要包含类型和权限位；身份与修改检查会拒绝哈希期间发生变化的文件。父目录链接和路径写法规范化可能把已记录的 Git 路径替换成另一个文件，因此 checkout 读取会拒绝两者，而不会把另一个文件的内容归到原路径名下。

原生工人空闲不代表宿主验证已完成。因此，即使较早模块或整合尝试已有终态证据，厂长行动等待仍跟随当前整合记录，直到整合结束。

Git 状态字母与工作文件哈希不能标识暂存内容。Crew 把[索引逻辑条目](https://git-scm.com/docs/git-ls-files)纳入 checkout 摘要，并在采集期间复查。摘要排除可变的文件状态缓存字节，避免正常 Git 刷新使证据失效。隐藏文件的标志会导致拒绝，并不授权清除用户管理的索引状态。提交准入比较完整摘要，获批的暂存步骤则单独保持已验证的工作文件不变。

整合测试可以位于所有开发模块之外。完整项目整合访问和开发者共享目录遵循岗位策略决策；原开发者 Session 继续负责模块返工。

工人到达需要处理的终态边缘时，记录并合并 Crew 厂长通知批次，在活动厂长回合结束后通过正常 Session 输入队列提交。进度变化只更新投影。这样无需常驻厂长进程或 MCP 自桥，也能保持“模型可见即记录”的规则。

Crew Web profile 在共享右侧栏注册属于 Session 的标签页。带类型的标签页导航保留任务与工人选择，并与现有工具详情标签页共存。Crew 视图提供实时、只读工人状态与证据；绝不挂载普通可编辑子输入框。审批仍是厂长对话中的工具操作。

命令退出码不能替代其他进程事实：超时进程仍可能以零退出。因此 Web 证据视图分别呈现退出码、信号与超时状态，将宿主保留的每条输出流作为纯文本显示，并各自提供截断提示。可折叠日志和有界滚动区域让后续证据仍可访问，而不新增工人交互入口。

一个结论不能标识它接受的规格、审查轮次或验证。只读视图保留这些已记录引用，以及每个审查或整合问题的预期修正。提交请求即使在暂存前被拒绝，仍会保留目标路径；UI 将其标为请求路径，另外显示已记录的提交哈希或拒绝原因，不从路径列表推断 Git 效果。

[交付决策](2026-09-06-native-crew-default-delivery.zh.md)将 Crew 与 Team 领域晋升到默认 Web profile；通用 Team 工具和 UI 仍是私有实验消费方。交付 profile 录制快照、重启矩阵、浏览器证据、硬策略测试、TypeScript/Python SDK 投影与真实 DeepSeek provider 冒烟测试共同固定当前行为。已实现的顺序与门禁见[核心开发步骤](../../../../docs/developer/discussion/agent-orchestration-core-development-plan.zh.md)。外部提供方结论与后续顺序见 [CLI 调查](../../../../docs/developer/discussion/agent-orchestration-cli-integration-research.zh.md)。

## 考虑过的替代方案

- 先实现 Claude Code，把其 CLI 进程同时作为厂长与工人。第一阶段拒绝，因为它在 DSH 原生生命周期证明前，就把产品状态设计与 UI 行为耦合到单个提供方的认证、传输、权限和版本。它仍是核心之后建议的第一个外部适配器。
- 为每个提供方实现专属 Crew 运行时。拒绝，因为现有子智能体 Service Definition 才是正确提供方接缝；Crew 应消费归一化可续接子智能体，而不是按产品名分支。
- 在 Session 数据旁把 `board.json` 作为权威。拒绝，因为两个持久权威会在部分写入或迁移后发生分歧；Session 事件已经负责回放和已发布数据兼容。
- 运行常驻厂长子进程并通过 MCP 暴露 Crew。拒绝，因为根 DSH Agent 已经是厂长，已有普通工具和 Session 输入，并可通过现有队列调度。
- 把软件阶段直接写进 Agent Teams 任务。拒绝，因为模块验证、审查、整合和 Git 策略是产品专属的；保持独立 Crew 投影能让 Agent Teams 继续通用。
- 允许用户导航并续接工人对话。此产品拒绝，因为单厂长交互模式是面向用户的不变量，而工人 Session 仍可通过只读投影检查。

## 验证

- 无密钥交付 profile 无需安装或登录外部提供方，即可运行一个厂长与多个 DSH 原生可续接工人；仓库内真实 provider 冒烟测试用 DeepSeek 运行同一原生生命周期。
- 重启测试从日志重建 Team、Crew、子智能体、验证、审查、整合、通知和提交状态，无需 `board.json` 或进程内权威。
- 策略测试覆盖工具筛选、范围文件操作、提交授权、定时器溢出以及冷恢复后的已记录进程限制。岗位策略决策负责当前 Windows 项目命令验证及不提供 OS 隔离保证的事实。
- 开发交接只有在宿主独立验证产物、变化路径和声明命令后才能推进。
- 审查打回返回同一开发子智能体；整合要求当前通过集合；提交要求静止、当前证据、通用用户审批和精确获批路径集合。
- 已记录的 Session 输入交付需要处理的通知批次，投影变化则无需厂长模型回合即可更新 UI。
- 浏览器测试保持现有右栏工具详情可用，并展示实时只读 Crew 状态而不暴露可编辑工人输入。
- 命令证据浏览器场景呈现已有的双模块录制，不改写原记录；中英文预期覆盖键盘展开、有界输出区域和刷新恢复。组件测试另外覆盖截断流、空输出、同时存在的超时/信号/退出事实，以及类似 HTML 的文本。
- 同一浏览器录制固定冻结工单引用、审查轮次和完整提交哈希；组件测试覆盖双语拒绝提交与审查/整合修正信息，不引入其他审批操作。
- TypeScript/Python SDK 预期、无密钥 Session 快照、预期工作区、包测试、浏览器测试和受影响双语文档覆盖同一套持久词汇。
- 第一阶段运行时不存在外部 provider 适配器、Gemini CLI、provider 登录和额度 UI。

## 后果

厂长、Team、Crew 投影与子 Session 现在共享同一个事件溯源运行时，因此恢复与 UI 状态不需要第二个进程、MCP 自桥或工作流数据库。代价是独立 Crew 投影，以及一个工具范围刻意窄于普通 DSH Session 的 profile。

共享 checkout 可能让测试看到另一个模块的半成品。因此派工要求真实路径互斥、独立聚焦测试、预先准备共享接口、重叠拒绝和静止整合。如果这些控制不能继续产生确定结果，必须通过新决定引入 worktree 隔离。

工具筛选可能看似安全，但不受限 shell 或文件系统别名能绕过。实现必须在执行时验证已解析操作与真实路径，并在终止和提交时再次检查 Git 事实；建议性 Team 写入范围不够。

厂长通知入队、交付标识与确认已持久化并与 Session 队列串行化。这增加了整值通知记录，但无需常驻厂长进程也能在每个已测试崩溃边缘保留交付。

Crew 必须继续消费共享 Team 与 Subagent 服务。重复实现其生命周期或持久化的变更需要新的架构决策。
