# Agent Note: HMR 浏览器测试恢复编译产物与增量状态

Status: implemented

[English](2026-09-05-hmr-test-restores-compiler-state.md) | 中文

## 问题

HMR 浏览器测试会修改 `ui-conversation/src/client/locales.ts`。监听器先将该源码编译到 `lib/types`，再打包为 `lib/client.js`。仅恢复源码和浏览器包会使编译产物及增量状态留在清理范围之外。后续增量构建可能报告项目已是最新状态，并将测试的 `HMR UPDATED` 文字打包进去，即使源码没有差异。

## 决策

`apps/web/tests/hmr-live.e2e.ts` 保存浏览器产物及被修改包的完整 `lib` 目录，包括类型编译产物与 `.tsbuildinfo`。清理先停止所拥有的监听器和 Host 进程，再恢复源码与生成文件。清理会删除所记录产物范围内新增的文件，恢复原始字节，并验证源码、产物路径、产物字节及现有完整构建摘要。清理错误会与交互错误一起使测试失败。

[客户端构建环境](../architecture/2026-08-18-client-build-environment.zh.md)仍负责公开变量和完整浏览器产物摘要。[无密钥浏览器测试通道](../testing/2026-07-24-web-gui-browser-e2e-lane.zh.md)仍负责回放与浏览器验收。摘要校验和无差异源码都不能证明中间编译产物与恢复后的源码一致。

## 考虑过的替代方案

**仅恢复浏览器包。** 后续打包器会读取未恢复的类型编译产物，重新引入测试文字。

**在监听器运行时恢复源码。** 编译器写入可能与清理重叠，留下仅部分恢复的生成文件。

**HMR 后清理整个检出目录。** 这会破坏无关的生成文件，并丢弃超出测试所修改包范围的增量状态。

## 影响

测试保留执行前的编译文件，不改变生产构建行为，也不生成替代的完整构建记录。真实浏览器断言仍要求源码修改可见且页面不刷新；清理额外逐字节比较记录的文件。若修改目标变化，整包记录范围必须随源码所属包调整。

测试会修改共享的检出目录，不能与其中另一项构建、监听器或浏览器使用者重叠执行；恢复已记录字节并不提供跨进程隔离。
